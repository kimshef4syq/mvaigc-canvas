# 内置 Agent：技能与 MCP 扩展

这版实现可安装的数据型技能和通用 MCP 连接管理，复用现有内置 Agent、画布命令、审批及执行回执。没有引入 iframe 插件节点，也没有迁移现有手动生成链路。

## 使用入口

Agent 面板右上角「更多」→「技能与插件」。桌面端提供本地安装和 MCP 连接；纯浏览器开发模式不提供本地文件/进程功能。

### 安装与调用技能

1. 填写安装 ID，例如 `film-director`。
2. 选择包含 `SKILL.md` 的单个文件夹，或选择 ZIP。ZIP 支持根目录直接放 `SKILL.md`，或只有一层包目录。
3. 也可以提供直接返回 ZIP 的 HTTPS URL 和发布者提供的 SHA256。目前不跟随下载重定向。
4. 点击「使用此技能」，输入框会加入 `$film-director`。也可直接输入「使用 film-director 技能分析剧本」，或使用技能声明的触发词。
5. 同名安装更新；可以禁用、卸载、恢复上一版本。

文件示例：

```markdown
---
name: film-director
description: 分析剧本并生成连续的分镜和参考图计划
trigger-words: [剧本拆解, 连续分镜]
allowed-tools: [canvas.read, canvas.write, generation]
---

先梳理人物、场景和叙事节拍，再输出镜号、时长和提示词。
需要参考示例时读取 references/shots.md。
调用画布工具时，只使用工具真实返回的节点和任务编号。
```

同时兼容 `triggerWords`、`activation`、`allowedTools` 和 `toolNamespaces` 元数据。`allowed-tools` 是依赖声明，不会注册工具或提升权限。不支持的依赖在管理界面和技能读取结果中显示。

内置与安装技能统一参与路由；明确指定优先，每轮默认选择最多三个技能。画布入口 `canvas_command` 始终注册，不依赖关键词是否命中；未命中时使用精简协议，模型可通过 `canvas_command_schema` 查询精确参数，也可根据技能索引调用 `skill_read` 加载指导。定位命令为 `viewport.focus`；仅兼容将明确的拼写误差 `viewbox.focus` 规范化，其他未知命令仍拒绝执行。正文按需读取，每次最多 12,000 字符，附件使用包内相对路径。技能脚本不会自动执行。

### 配置 MCP

1. 添加连接 ID、名称、连接方式。
2. stdio：填写可执行程序和 JSON 参数数组，例如程序 `/path/to/python`、参数 `["/path/to/mcp_server.py"]`。宿主直接启动程序，不经 shell 拼接命令。
3. HTTP：填写服务提供的 Streamable HTTP 端点。本机可使用 HTTP，远程要求 HTTPS。不是任意网页 URL，也不支持旧版独立 SSE 端点。
4. 保存后点击「连接并发现工具」。首次连接不会自动授权任何工具。
5. 勾选允许 Agent 使用的工具，点击「应用工具授权并重新连接」。工具在下一轮 Agent 请求中注册。
6. 在对话中说明要调用哪个服务、完成什么任务。手动模式显示确认卡；自动模式遵循现有自动执行策略。

本版暂不支持 OAuth、自定义认证头、环境变量配置和 MCP 安装脚本；运行依赖及软件本体需事先准备。配置和工具授权持久保存。Agent 任务开始前会按需重连已有工具授权的服务，再读取本轮工具目录；首次未授权的服务不会自动启动。用户手动断开后，本次应用运行期间不自动重连；显式连接可以解除这一限制。重连失败不会阻断画布功能，模型会收到脱敏的连接状态和错误。

MCP 工具使用独立名称，附带服务 ID、原工具名及实际参数 schema。配置或工具目录变化会令旧调用失效。模型输出规范化也接受本轮实际注册的动态工具，避免被原先的固定四工具白名单丢弃。

模型引用旧对话里的失效工具名时，宿主将其转换为 `agent_tool_unavailable` 反馈，提供当前目录及连接状态；原调用不会执行。相同失效工具连续调用三次会明确停止，避免静默丢弃后空转直至达到最大轮数。

授权工具超过 8 个时，Agent 先通过 `mcp_tools` 按服务或关键词查找，每次加载最多 8 个工具定义，避免每次请求携带整份工具目录。

检查全部工具时，使用 `mcp_tools` 的 `mode: "inspect"`，通过 `nextOffset` 翻页检查参数定义。目录检查不执行工具；实际调用测试优先使用状态查询。需要测试素材或可能修改软件/文件的工具应标记为「未执行」，不能为了测试连接而生成、删除文件或启动渲染。

审批记录始终绑定模型原始 JSON 参数。界面中的脱敏参数只供展示，不能用来重建执行审批；工具执行前的参数解析、默认值和字段过滤也不能改变原始请求的审批指纹。兼容接口返回的二次编码 JSON 对象会规范化；只有明确没有参数的工具允许把 `null` 或空数组转换为 `{}`，其他非法参数仍拒绝执行。

恢复中断审批时重新注册宿主工具及已授权 MCP 工具，不依赖恢复提示文本的技能关键词；原有参数校验和审批约束继续生效。

### 画布成品图交接至达芬奇

存在已授权的 `run_script` 工具时提供 `mcp_davinci_append_images`。Agent 先用 `asset.list {kind: "image", generatedOnly: true}` 查询成品 ID，再提交 `serverId`、`assetIds` 及可选 `durationSeconds`（默认 5 秒）。目录返回 `purpose` 和 `availability: "unchecked"`：有引用不等于文件已经验证。成品通过生成文件名、生成记录或来源提示词等元数据识别；导演台新截图明确标记为 `intermediate`。宿主也会过滤非成品素材，并返回 `skippedAssets`，避免模型混选时尝试读取缺失截图。

宿主验证服务是本机 stdio 官方 `ResolveMCP`，通过 `prepare_external_image_source` 检查原图可读、可解码及尺寸，在应用 `external-media/images` 目录保存全分辨率 PNG（不受画布孤立图片清理影响）。固定 Python 脚本使用 `MediaPool.ImportMedia([path])` 导入单张文件，追加到当前时间线末尾的最上方视频轨道；不创建或切换时间线。没有视频轨道时创建一条。文件路径只在宿主与 MCP 之间传递，不进入模型上下文。Resolve 21.1 实测单张图片应使用路径列表，原先仅提供 `FilePath` 的字典形式未返回图片。

该入口沿用外部工具审批和执行回执；返回 `stage`、`outcome`、`error`、媒体池 `imported` 数量、时间线 `appended` 数量及时间线名称。本地文件预检失败明确记为失败且不调用 MCP；脚本返回结构化阶段错误，无法解析回包或追加调用中断时才保留未知结果，具体 Python 错误不再统一覆盖为泛化提示。部分成功或结果未知时不得自动重放整批导入。`asset.locate` 仅用于画布导航，不负责查询文件路径；兼容丢弃其多余的布尔 `reveal` 字段，其他非法参数仍由命令契约拒绝。

## 存储与限制

- 使用 Tauri 应用数据目录中的 `extensions/skills/<id>/` 和 `extensions/mcp.json`，不依赖工作区或当前项目路径。
- 技能下载/解压上限 32 MiB、单文件 2 MiB、512 个文件；`SKILL.md` 上限 128 KiB。禁止包内越界路径和符号链接。
- 技能安装先写入临时目录，验证结构后切换；上一版本保留用于恢复。无效技能独立报告，不阻断其余技能。
- 安装技能目录有内容版本指纹，运行中的资源读取校验版本和启用状态。目录缓存由管理操作刷新，避免每个模型请求都扫描文件。
- MCP 连接最长等待 30 秒，工具发现 20 秒，工具调用 120 秒。长渲染任务应由服务返回任务句柄，再调用查询工具。
- MCP 写入复用审批和幂等回执。断线/超时标记结果未知，同一调用 ID 不会自动重放；无法据此保证任意服务的所有副作用具备跨服务“恰好一次”语义。
- 大型素材仍使用画布原有资产管理。通用 MCP 输出继续经过脱敏；本机官方达芬奇已支持上述原图交接，视频、Blender、远程 MCP 的素材交接仍需具体适配。
- 本版不包含完整的剧本到成片持久任务编排，也不自动安装 Blender/达芬奇专用 MCP。具体服务选定后，接入真实软件做兼容性验证。

## 验证

前端测试覆盖 YAML 解析、显式/触发词选择、依赖边界、动态工具名、MCP 审批和未知结果防重放。Rust 测试覆盖 ZIP 越界、符号链接、失败安装保留旧版本，以及通过真实 stdio 子进程完成 MCP 握手、工具发现和调用。
