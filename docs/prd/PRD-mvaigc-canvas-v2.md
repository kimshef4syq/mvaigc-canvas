## 1. 背景与目标（Why）

### 1.1 行业痛点
传统 AI 创作工具多以线性对话窗口或单次表单为主，在影视编导、分镜师与视觉团队的实际生产中存在明显断点：
- **上下文割裂**：角色设定、分镜参考图、提示词变体与成片视频分散在不同历史记录中，难以保持人物与场景一致性。
- **资产不可溯源**：生成结果脱离了当时使用的母本参考图、模型与参数组合，无法快速分支派生或批量微调。
- **多供应商接入成本高**：创作者往往同时依赖融媒视界、中转站 API、ComfyUI 本地/云端工作流及外部 Agent，切换成本与重复计费风险高。

### 1.2 核心目标
打造一款**本地优先、无限可扩展、全链路可溯源**的桌面端 AI 影视与分镜创作画布（基于 Tauri 2 + React + Rust），将素材管理、多模型图文/音视频生成、3D 导演台预演、3DGS 高斯泼溅与画布 Agent 统一于同一视觉工作空间。

## 2. 目标用户与典型场景（Who & When）

| 用户角色 | 核心诉求 | 典型工作流 |
|---|---|---|
| **AI 影视导演 / 分镜师** | 视觉化统筹镜头节奏、角色一致性和运镜构图 | 上传角色母本 → 多角度/打光派生 → 分镜拆解 → 导演台 3D 预演截图 → 图生视频 |
| **AIGC 视觉创作者** | 便捷切换多模型与提示词预设，安全保存本地资产 | 提示词库/批量导入 → 生图节点对比 → 宫格切分 → 3DGS 高斯泼溅建模 |
| **技术美术 / 本地算力玩家** | 接入本地或云端 ComfyUI 工作流与自定义中转站 | 导入 ComfyUI API Format 工作流 → 自动映射输入输出 → 本地渲染出图/视频/音频 |
| **开源二次开发者** | 清晰扩展新供应商、新节点、MCP 工具与技能插件 | 按 `CAPABILITY-MAP.md` 与各模块 Spec 扩展模型、节点或 Agent 技能 |

## 3. 范围定义（Scope）

### In Scope（v2.2.x 核心能力矩阵）
1. **无限可视节点画布（`canvas-core`）**：支持上传、AI 生图/生视频/生文本/生音频、分镜拆解、全景、3DGS 高斯节点、蓝图、标签/标签组与导出结果节点；支持几何索引优化、撤销/重做与任务可恢复状态机。
2. **多供应商与内置反代（`ai-providers-proxy`）**：内置 Rust `axum` 驱动的 `mvaigc-proxy`（账号密码一键接入融媒视界）、ComfyUI 工作流适配、MiniMax H3 官方视频接入、自定义 OpenAI 兼容及中转站图片契约。
3. **3D 导演台与预演系统（`director-previs`）**：3D 空间/全景背景中的人物、动作、灯光、摄影机路径与时间轴预演，支持预演视频导出与截图回传画布。
4. **3D 高斯泼溅工作流（`3dgs-supersplat`）**：嵌入 SuperSplat 3DGS 编辑器与图转 3DGS 管线。
5. **画布 Agent 与扩展生态（`canvas-agent-mcp`）**：右侧对话式 Agent（手动审批 / 自动模式）、可安装技能（`SKILL.md`）与通用 MCP 客户端（stdio / Streamable HTTP）。
6. **本地持久化与工程迁移（`persistence-portability`）**：基于本机 SQLite 的工程存储、视口轻量持久化、工程包导入导出与设置备份（默认脱敏不导出凭据）。
7. **提示词库与批量导入（`prompt-library`）**：影视语典、预设提示词模板自定义与表格批量导入生图任务。
8. **应用设置与双语本地化（`settings-i18n`）**：中英文切换、主题皮肤、鼠标交互预设、网络路由与脱敏日志诊断。

### Out of Scope（明确边界）
- 不提供云端账号同步系统或云端工程托管（所有工程与凭据严格本地存储）。
- 不内置绕过第三方供应商鉴权、风控或内容审核的机制。
- Agent 自动模式不免除第三方供应商费用，且禁止在提交状态不明时自动重发计费请求。

## 4. 非功能性约束与验收标准

1. **计费安全**：异步生成任务状态机（`queued` / `submitting` / `running` / `recoverable_wait` / `materializing` / `succeeded` / `failed` / `unknown`）在提交结果未知时，严禁自动重发请求；提供安全的任务恢复与脱敏日志查询。
2. **数据安全与隐私**：设置备份默认不包含明文 API Key / Token；仅在用户明确确认风险后方可导出/导入凭据。
3. **双端与双运行态兼容**：桌面端（Windows / macOS via Tauri 2）走 SQLite 与 Rust 原生能力；纯浏览器开发模式（`npm run dev`）降级至 Web 存储并保持基础界面可运行。
4. **大画布性能**：节点拖拽中不触发全量重持久化；视口变更走轻量命令 `update_project_viewport_record`。
5. **工程门禁**：所有变更需满足 [CONSTRAINTS.md](../../CONSTRAINTS.md) 定义的类型检查、单测、Rust 编译与 LF 换行符要求。
