# AI4AnimationPy 双足动画移植

本地非商业验证版本。上游代码、预训练网络和人物资产采用 **CC BY-NC 4.0**，不属于项目原有许可证的重新授权范围。发布商业版本前需要另行获得相应授权或替换这些组件。

## 使用

1. 打开导演台的模型库，选择「基础人物」中的 **Geno · AI 动作** 或 **Cranberry**。
2. 切换到「预演台」，选中已加载的 Geno，点击「AI 角色操控」。首次进入会加载两个本地 ONNX 网络。
3. WASD 移动，Shift 加速，Q/E 切换动作风格，右键拖动调整朝向；Esc 退出。风格也可以通过下拉框选择。
4. 将播放头置于要开始录制的时间，点击「录制动作」。以 30 FPS 保存最终根变换和 23 个关节的局部变换；到时间轴末尾自动保存。再次录制替换这个角色的上一段骨骼录制。
5. 退出操控后可拖动时间轴、循环播放，或删除骨骼录制。录制范围内骨骼数据覆盖该角色的路径与姿态轨道。
6. 点击「保存工程」持久化；配置至少两个摄像机关键帧后，使用既有「录制」功能导出 720p / 1080p、24 / 30 FPS 视频或添加到画布。

Cranberry 首版只支持模型展示和场景变换，不使用 Geno 网络。程序化人物及旧 GLTF 人物保持原有行为。此版本未包含任意骨架重定向、四足控制器、碰撞或地形适应。

## 移植边界与数据

- 上游：<https://github.com/facebookresearch/ai4animationpy>，固定提交见 `public/models/ai4animation/manifest.json`。
- 模型文件：Geno、Cranberry 的 GLB 保持不变；骨架定义和上游许可与资产一起归档。
- 主网络：441 维输入，4464 维输出；16 帧、0.5 秒的未来序列，固定三次确定性迭代，每秒预测 10 次。
- 接触网络：456 维输入，64 维输出；4 个足部接触值 × 16 帧。接触值裁剪到 [0,1] 后取三次方。
- 模型内部归一化保留在 ONNX 图中，前端不重复归一化。根增量的 yaw 为角度；Three.js 运算转换为弧度。
- TypeScript 移植轨迹控制、特征拼接、序列解码与混合、骨长/方向恢复、脚踝与脚趾 FABRIK。Three.js 以正交四元数表达姿态，回放采用四元数插值。
- 两个网络按需异步加载、串行推理；渲染采样最近序列，取消后丢弃过期结果并释放推理资源。无需 Python 服务或 Rust 动画后端。
- `BlueprintItem.presetId` 使用 `ai4animation-geno` / `ai4animation-cranberry` 识别模型。`DirectorMotionProjectV1.skeletonRecordings` 是可选字段，旧项目继续可读取。
- 每段录制记录 `modelId`、`skeletonId`、`fps`、`jointNames` 和 `frames`；每帧包含时间、根位置/四元数/缩放及按关节顺序排列的 `xyz + xyzw` 局部变换。
- 导出和随机时间回放直接读取烘焙数据，不重新运行模型。录制正常保存为导演台工程后，随项目数据一起持久化。

## 重建资产

客户端只需要 `public/models/ai4animation/` 和 Vite 打包的 ONNX Runtime WASM/MJS。模型总计约 48.4 MB，两个 GLB 合计约 1.1 MB；另有约 14.2 MB 的 WASM 引擎。

离线重建使用 Python 3.12，在独立虚拟环境中安装 `scripts/ai4animation/requirements-export.txt`。克隆官方仓库并检出脚本中的 `PINNED_REVISION`，然后运行：

```sh
python scripts/ai4animation/export_biped_onnx.py --source /path/to/ai4animationpy
```

脚本核对提交，加载可信的官方 PyTorch checkpoint，导出 opset 17 静态 ONNX，验证模型，执行 PyTorch / ONNX 数值对照，并更新资产 SHA-256 清单与参考测试数据。只从固定官方来源加载 checkpoint；它们使用 Python pickle。

## 动作库坐标与姿态验收

动作参数以人物坐标为基准（+Y 向上、+Z 向前、+X 为人物左侧），不直接代表导入骨骼的本地欧拉角。Geno 的参考姿态将双臂及手腕校准为约 11° 的自然外展下垂、大腿和小腿校准为垂直方向，再通过父骨骼参考旋转转换动作参数。参考旋转由人物内部层级计算，人物首次带旋转或非等比缩放加载时也不会改变关节轴。

- 躯干从髋部向上延伸，与向下的四肢使用不同的前屈符号；前倾、后仰、鞠躬已按实际头部位移检查。
- 肩部采用 XZY 顺序，使扭转发生在抬手与侧展之前；重新校准叉腰、抱臂、鼓掌、电话、侧步、深蹲和跪姿参数。鼓掌检查包括完整周期的双手前向位置、开合距离与左右手不穿过彼此。
- 坐跪、深蹲与有支撑的步态在踝部补偿髋膝弯曲，并根据脚踝、脚尖与膝部支撑点调整高度。这里是平地 FK 姿态补偿，不是地形 IK 或物理求解。
- 场景初始化、元素更新和时间轴采样都合成动作的整体旋转、竖直偏移与纵向缩放。躺下旋转不再被覆盖，且在人物路线朝向下仍保持正确。进入 AI 操控时去除静态姿态对根节点的旋转、下沉和拉伸；神经网络与烘焙帧使用直接骨骼路径。
- 旧工程中与旧默认值完全一致的内置姿态快照会在规范化时升级（立正、叉腰、抱臂、深蹲、单膝及双膝跪）；用户修改过的参数保持原样。

`neuralCharacterAssets.test.ts` 读取实际 Geno GLB 的层级与变换，对上述方向、手腕目标区域、落地支撑、人物根变换和模式切换做回归检查。浏览器使用实际蒙皮模型与场景同一套变换函数，检查 24 个静态姿态的正/侧视图、13 个动作每周期四个阶段，共 100 个画面。

可复现的视觉检查：先用 Playwright CLI 在独立检查页打开开发地址，再执行 `run-code --filename scripts/ai4animation/action-library-audit.js`。该脚本仅替换检查页 DOM，不修改项目。结果见 `output/playwright/geno-static-poses.png` 与 `output/playwright/geno-procedural-actions.png`。神经网络检查仍使用 `browser-smoke.js`；此次 WASM 误差约 `4.3e-6` / `4.8e-7`，烘焙回放误差约 `1.1e-8`。Cranberry 仍为模型展示范围。

基础姿态验收增加实际蒙皮检查：自然站立、立正与完整呼吸周期的手部顶点均保持在同侧腿部正面轮廓之外，至少保留 5 mm 间隙；同时检查手腕外侧距离和指尖方向。手腕参考旋转通过中指指尖方向校正，不改写原模型的手指关节形状。新的参考姿态下重新校准了鼓掌闭合幅度和电话手势。

## 手腕与手指动作

Geno 支持左右手独立手腕旋转（弧度：X 向掌心屈曲、Y 沿手指方向扭转、Z 向拇指侧偏），五指各自的三段关节弯曲、指间张合和拇指对掌。手指参数为 0–1，张合为 -1–1；弯曲轴由实际手掌、指骨方向推导，左右手分别校准。省略新字段时保留原姿态，旧工程仍可打开。

动作库增加「张开双手」「双手握拳」，并为指向、挥手、电话和鼓掌接入手指与手腕动作。自定义姿态编辑器增加左右腕及五指滑块，提供放松/张开/握拳/指向/握持快捷设置；实时预览使用 Geno，AI 姿态 JSON 提示词和导入支持相同字段。自定义动作关键帧会保存并插值这些通道。

AI 操控面板可独立选择左右手手势，约 0.1 秒平滑切换；这是本地手势层，原 23 关节神经网络不变。新录制使用 `geno-biped-hands-53-v2`（23 个身体关节加 30 个指骨），保存最终本地变换，时间轴及画面导出直接回放。旧 `geno-biped-23-v1` 录制兼容，回放时会清除未录制的指骨残留。V2 录制验证完整骨骼名称、帧宽度与指骨四元数。

手部回归检查使用实际 GLB：左右掌心方向、独立手指/拇指控制、指向保持食指伸直、手腕屈曲方向、握拳后恢复、53 关节保存/回放/随机采样，以及旧录制兼容。可用 `scripts/ai4animation/hand-pose-audit.js` 生成近景 `output/playwright/geno-hand-gestures.png`。

本次手部界面验收：预演台「动作库 → 手腕与手指编辑」中修改并保存指向手势与手腕角度，已写入动作关键帧；实际 AI 操控中切换右手握拳/指向、左手张开，录制 44 帧，保存工程并刷新重新打开后轨道恢复。960×600 窗口下手势与录制控件可操作。浏览器网络数值检查保持通过，53 关节烘焙回放误差约 `1.1e-8`。

## 原仓库动作与连续控制器对齐（2026-10-14）

此前动作库的站坐蹲、鼓掌等是手写角度／正弦动作，并非原版动捕；现在将它们标为「程序化动作」，保留旧工程行为。新增优先显示的「原仓库动作」：走路、跑步、冲刺、瞄准、地面动作，来自固定上游提交的 Geno/Motions 五份完整 NPZ。原始帧率约 59.9988 FPS，包含开头／结尾的校准姿势；可预览和选择任意源片段，不自动删除这些帧。按源文件最近帧采样（含 NumPy ties-to-even），只做片段起点的刚体定位，不施加自然下垂重定向、人工踝部落地补偿或手势。选择的片段在当前播放头以 30 FPS 烘焙，裁剪至工程末尾，沿用每个角色一段骨骼录制的替换行为。源动作按需加载，新增约 44.6 MB 的本地 float32 数据。

连续计算恢复原 Python 行为：预测前控制／纠正轨迹、矩阵轴插值与独立归一化、相对序列时间推进（含首次前后序列别名）、平滑收敛阈值、保留非正交预测轴的特征和接触计算，以及在链根矩阵空间执行 FABRIK。浏览器按串行固定步进等待所需预测完成，再动画，避免使用上一序列先动画而改变反馈输入。最终蒙皮骨骼使用准确局部矩阵，AI 默认手势为「原版」，手势选择才叠加五指控制。

录制帧增加可选 `jointBases`（每关节 9 个列主序元素），保留局部矩阵，不因转成四元数而损失原版姿态；仍保留 `xyz + xyzw` 和旧 23／53 关节格式。旧录制缺省此字段时继续使用四元数回放。原版录制另存可选 `source` 来源信息，时间轴显示原版动作名称。随机回放和视频导出直接使用保存的矩阵。
