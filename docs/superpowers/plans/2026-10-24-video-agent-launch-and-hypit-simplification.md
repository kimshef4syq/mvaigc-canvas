# 从视频节点打开外部智能体：入口简化与 Hypit 架构收尾计划

状态：用户已于 2026-10-25 授权开始实施。入口、自动准备、授权与可靠性修复已实现；验收范围见后续验证记录。计划本身不代表付费生成、发布或推送已获授权。
日期：2026-10-24

## 1. 要解决的问题与交付目标

用户不应寻找 Hypit 目录、复制 MCP 配置、拷贝 Provider、安装依赖、合并 Runtime 或重复输入 mvaigc 账号。日常入口是：

> 上传视频 → 视频节点菜单「用智能体复刻此视频」→ 选择 Claude Code / Codex → 直接描述需求。

第一次记住默认智能体；以后默认一键打开，可从菜单切换。系统自动准备当前画布的工程、连接、参考视频和制作能力。智能体打开时已经知道“哪张画布、哪个视频、在哪里工作、如何生成和回写”。

成功标准不是按钮能打开终端，而是从一个尚未配置 Hypit 的新画布出发，完成真实视频取料、方案、生成、预览与回写，用户无需执行配置命令。

## 2. 现状与评审结论

已具备、继续复用：
- 画布对应的 Hypit 工程目录、MCP broker、asset_read、assets_import、成品打组。
- Claude Code 的 local-scope MCP 配置写入；Codex 的连接配置生成。
- 独立 mvaigc Provider：端口转换、异步提交/轮询/收集；画布本地反代对接 mvaigc。
- SDK 加载测试 bootstrap；图片、视频、回写已有真实执行证据。

尚未完整具备：
- 从视频节点打开外部交互式 CLI 的统一入口。现有画布内子进程会话不是“打开一个用户可交互的外部终端”。
- Codex 的 Hypit 技能准备与零手贴连接。
- 新工程的 Provider/Runtime/授权自动准备。当前只自动创建工程标记，不等于制作环境就绪。
- 端到端取料的明确验收记录；不能沿用“接线测试通过”当作它已通过。

架构判断：保留“画布物料桥接 + 独立 Hypit Provider + 共用 mvaigc 反代”。问题主要是准备流程暴露给用户、版本与授权重复配置，以及若干可靠性缺口；不推倒重写。

## 3. 用户流程与默认行为

### 3.1 入口

- 上传视频节点、普通视频节点、已生成的 AI 视频节点，只要有可用视频素材，都可进入。
- 一级操作：「用智能体复刻此视频」。已有默认智能体则直接使用；首次选择 Claude Code 或 Codex，记住偏好。
- 二级选择允许临时换智能体，不改变用户的模型、Router 或供应商设置。
- 画布菜单保留「打开工程智能体」，用于没有指定参考视频的任务。
- 生成中、没有可用视频、素材已丢失时显示明确原因；不打开一个缺参考的空会话。
- 多历史版本节点以当前展示版本为准；启动时固定 assetId 与版本，之后切换主视频不悄悄替换本次参考。

### 3.2 准备过程

按钮后最多出现一个进度提示：检查环境 → 准备工程 → 连接画布 → 准备参考 → 打开智能体。

- 检测智能体 CLI、Node/Hypit、技能、Provider、画布服务与授权。
- 已满足则复用；不重复安装或覆盖用户已有配置。
- 缺程序、未登录、网络不可用等只展示当前阻塞项及对应修复动作。
- 不在点击时静默执行不受控的全局 npm 安装；缺少外部运行时通过明确的一次性设置动作解决。
- 首次下载/准备若失败，保留可重试状态；重试不产生第二套工程。

### 3.3 智能体开始对话时

传入简短的任务说明与一个启动清单路径，包括项目 ID、参考资产 ID、素材本地路径、制作方式和回写约定。不要把整个画布、全部技能文档、图片 Base64 或视频内容作为长文本塞进初始上下文。

智能体首先复述已识别的参考与任务范围；用户没有给出创作目标时再询问目标，不默认消耗生成额度。若用户已明确要求直接生成，沿用该授权，不额外固定增加确认步骤。

### 3.4 成品与回写

沿用当前约定：成品准备好后提示，用户说「推回画布」再导入、打组。复用现有写操作审批，不另加一套确认机制；若后续要将“完成后自动回写”作为可选设置，单独评审，不在本次默认开启。

## 4. 职责边界与实现结构

| 层 | 负责 | 不负责 |
|---|---|---|
| 节点菜单/连接面板 | 选择参考与智能体、展示准备状态 | 模型端口转换、凭据处理 |
| 启动编排 | 按顺序确保工程、环境、连接、参考、启动；复用与失败恢复 | 复制一份生成引擎 |
| Canvas bridge | 元数据查询、原始素材落盘、成品导入、项目权限 | Hypit 的故事/剪辑判断 |
| Hypit Provider | Hypit 能力 → 本地服务请求；异步任务生命周期 | 操作节点、直接调用 mvaigc 私有接口 |
| mvaigc 反代 | 唯一的上游登录、上传、私有协议与任务状态转换 | 理解 Hypit 剧本与工程文件 |
| Hypit | 制作方案、生成调度、组合和导出 | 管理画布 UI |

新增一个薄的启动编排模块与两个 CLI 启动适配器。复用现有连接、物料导入导出和运行时诊断；外部终端启动可以新增入口，但不能复制画布内会话管理器。

开发中如果同一模型规则开始分别写进节点、Provider 和反代，应先明确规则所有者；上游模型 ID 与私有参数细节归反代，Provider 只保留必要的 Hypit 端口适配与能力约束。既有前端模型选择逻辑不趁机重写。

## 5. 核心设计决策

### 5.1 工程、会话与连接绑定

- 工程身份以稳定 projectId 为准，项目改名不创建第二个工程。兼容已有 slug 目录，建立映射或优先复用既有路径，不自动搬动旧文件。
- 同画布、不同视频共用工程，每次任务有独立 reference/task 标识。
- 启动清单只记录资产定位、必要元数据与路径；不含长期密码或 token。
- 连接描述符必须绑定启动时的 projectId/sessionId。新打开另一个画布不能让旧终端通过全局 current 描述符误连新画布。
- 优先复用现有 broker 的会话隔离；若现有实现只支持单活动画布，首版明确阻止冲突或让旧连接失效并说明原因，不能声称已支持并行多画布。
- 画布关闭/连接过期时明确报“连接不可用”，保留已有工程和上游任务 ID；不偷偷重提生成。

### 5.2 CLI 与终端启动

- 首版交付 macOS 的 Claude Code、Codex 交互式 CLI；Windows 的终端启动单独列兼容任务，不宣称已验证。
- 只支持“外部 CLI 终端”这一种启动形态；本次不承诺打开 Codex 桌面 App、IDE 或任意第三方终端。
- 进入工程目录，通过当前 CLI 支持的机制注入会话级 MCP 和初始任务。实施前查看本机帮助，验证真实参数，不在计划里假造通用启动参数。
- 优先会话级/项目级注入，不覆盖全局已有 MCP、模型和 Router。确需写配置时保留无关字段、原子写入，损坏配置原样保留并报错。
- 所有用户路径按参数/可靠的系统机制传递；验证中文、空格、引号等，不将提示词和路径直接拼成可执行 shell。
- 首次信任目录/CLI 登录等属于外部工具自身行为，明确引导，不绕过其安全提示。

### 5.3 Provider 与技能的安装、版本管理

- 构建时产出可直接使用、版本固定的 Provider 包，纳入发布资源；发布版不能依赖开发仓库路径。
- 采用“共享的不可变版本缓存 + 工程依赖锁定”。利用包管理器已有机制，不自建插件市场或泛化包管理器。
- 工程记录 bootstrap 版本、Provider 版本和兼容的 Hypit 版本；使用应用管理的配置区，保留用户编辑内容。
- 首次自动准备，后续复用。升级先验证新环境，再切换版本；已有工程保留锁定版本与回退路径，不启动即强制升级。
- Claude Code/Codex 各自确认技能发现路径与调用方式。优先项目局部发现，避免覆盖用户自己维护的全局技能。
- 技能源固定来源与版本；检查可分发性。若不能随应用分发，则通过一次性、版本固定的安装步骤获取，并在 UI 中说明。

### 5.4 授权与本地服务地址

目标：用户只在画布设置登录一次 mvaigc，不再到 Hypit 重复填写账号密码。

- 长期账号密码继续由现有画布凭据机制管理。
- Provider 通过项目/连接范围的本地授权访问反代；建议复用或扩展已有 broker 授权机制，先验证可行性，避免再实现一整套认证系统。
- 若需要短期令牌，它只授权本地生成服务，通过受控凭据通道交给 Provider；不写入提示词、BRIEF、启动清单或日志。
- 令牌的范围、有效期、撤销与长任务轮询恢复必须一起设计。旧 account:password 接入保留兼容，不在新入口继续复制长期密码。
- 由连接准备过程解析实际反代端口并生成配置，不再手工同步 8787。地址变化可重新准备连接，首版不必实现复杂热更新。

### 5.5 制作方式：简化使用，不再建第二套引擎

- 默认「快速复刻」：少量代表画面分析 → 简短可执行方案 → 按目标生成 → 预览。仍复用现有 Hypit/Provider 能力。
- 「完整制作」用于多镜头精确剪辑、字幕、配乐等；按需展开，不要求每次加载全部流程。
- 快速复刻不是逐帧一致保证；参考视频长于模型单次输出能力时，说明片段/拆镜方案，不悄悄截短。
- 本次不新建“另一套快速生成后端”，也不自动覆盖用户配置的模型。

### 5.6 上下文与视觉输入预算

- 先读取有上限的元数据和一张压缩总览；初始总览建议 8–12 个代表帧，之后按需补充少量局部。确切尺寸与预算通过真实模型验证后固定。
- 禁止将图片 Base64 作为普通文字回传；视频/音频以本地文件交接。
- 不默认生成、读取频谱图；有语音需求再使用可用转写能力。
- 同一参考已有分析与证据则复用，源文件变化后失效；保留原始素材，不用压缩总览替代生成参考原图。
- 识图能力缺失/网关处理不正确时明确停止视觉分析并给出修复提示，不能伪造“已经看过”。
- 本机 Router 的现有 bundle 热补丁是独立环境修复，不纳入画布生产实现。产品不修改第三方安装目录；长期应使用上游修复或单独维护的固定版本。

## 6. 可靠性修复清单

### R1. 模型能力与输出参数一致

- 图片固定 2K 是明确能力限制，在方案预览中可见；不让显式 1K/4K 请求在无说明时变成 2K。
- 输出格式由上游决定时标为不可保证，明确冲突的请求在提交前处理，结果记录实际 MIME/格式。
- 视频分辨率、首尾帧、参考素材与音频组合在预检和真正提交使用一致规则。
- 保留 SDK bootstrap，测试真正的 supports/start/poll/collect 与凭据 secret 解析；删除“SDK 无法测试”等失实注释。

### R2. 任务查询与恢复

- 优先调查是否存在可靠的按 ID 查询接口；若没有，使用有上限的历史分页查询与明确的 not_found/暂不可见状态。
- 不再把“最近 50 条找不到”无限解释为 processing。
- 区分刚提交的可见性延迟与长期查无任务；到达查找预算后给出可恢复状态与原因，禁止自动重提付费任务。
- 保留远端任务 ID、阶段与必要时间，恢复优先 poll/collect；无上游幂等保证时，明确保留“提交结果未知”的状态，不能宣称 exactly-once。
- 上游只返回“生成失败”时如实保留，不猜测审核或余额原因。

### R3. 错误与可诊断性

- 区分环境准备、素材读取、鉴权、提交、轮询、下载、画布导入阶段。
- 一次任务有贯穿各层的 trace/task 标识；保存项目 ID、参考资产 ID、模型/实际参数、上游任务 ID、阶段及脱敏错误。
- 错误视图面向用户给出下一步；详细日志可展开。禁止记录账号密码、Bearer token、签名下载 URL 和完整媒体编码。
- 生成成功但回写失败时，保留成品并允许仅重试导入；不得重新生成。

### R4. 素材桥接与回写幂等

- 真正执行 asset_read 读取上传视频，确认 imports 下的文件可播放、不是缩略图、内容与源一致。
- 同一素材重复准备复用导出；检查已有缓存有效性，不仅看文件名存在。
- 继续拒绝 FIFO、目录、符号链接等非普通导入文件；大文件不能堵塞 UI。
- 重试同一批成品回写不重复创建节点/组：优先复用现有命令回执或增加明确的 operationId，不以文件名猜测去重。

建议按 P0 → P1 → P2 → P3 → P4 顺序实施。不为赶按钮效果跳过新工程验收；每阶段单独可审查、可回退。不要在实施前编造工期：P0 输出确定的接口与剩余工作量后再估时。

## 9. 验收矩阵：必须以证据通过

| 场景 | 预期 |
|---|---|
| 新画布 + 上传 mp4 + Claude Code | 无手动 cd/复制配置；选定视频可读；正确工程与画布 |
| 同样流程 + Codex | 不依赖 Claude 专属技能目录；能力与连接确实可用 |
| 视频多历史版本 | 读取启动时所选版本 |
| 同画布再次打开/换参考 | 工程复用；当前参考正确；用户文件保留 |
| 项目改名 | 工程身份不变 |
| 切换画布后旧终端回写 | 不会写进新画布；隔离或明确拒绝 |
| 缺 CLI/技能/Provider/账号/网络 | 准确指出阻塞项；重试可恢复，不出现半成品“已就绪” |
| 中文、空格、引号路径 | 正确启动；路径不成为 shell 指令 |
| 反代换端口/应用重启 | 重新准备后恢复；无密码泄露；不重提已有任务 |
| 任务在最近 50 条之外 | 查到终态或明确报告不可定位，不无限等待 |
| 生成成功、回写失败、再试 | 只重试导入，不生成第二次、不重复节点 |
| 图片 1K/4K、格式冲突、视频非法组合 | 提交前明确处理，实际参数可追溯 |
| DeepSeek 经 Router 的参考分析 | 代表图真正可识别；上下文预算受控；不把 Base64 计为文本 |
| 完整制作 | 仍能使用已有多镜头/合成能力，不被快速模式破坏 |
| 应用更新/旧工程 | 原 Provider 锁定版本可用，用户配置不被覆盖 |

验证分三层：
1. 单元/契约测试：参数、能力、配置合并、版本、凭据、任务恢复与异常路径；使用真实 SDK 加载。
2. 集成/UI 测试：菜单→准备→启动、重复点击、错误恢复、模拟进程与服务；不消耗生成额度。
3. macOS 真机验收：两种 CLI 各完整跑一遍上传视频→取料分析→真实生成→预览→回写打组；记录脱敏任务 ID、输出尺寸/时长和画布结果。测试素材与付费生成次数在执行前列明，沿用当时用户授权，不把计划评审当作无限生成授权。

“单测全绿”不能替代第三层，也不能把只验证过图片的结果写成视频全链路通过。

## 10. 迁移、回退与暂不做的事

- 旧连接、手动打开工程、已有 Provider 安装继续可用；新入口不删除旧数据。
- 新自动准备不覆盖已有 BRIEF、脚本、产物和无关 Runtime 服务。
- 迁移前保留受影响配置备份；失败恢复原引用。首版允许关闭新入口继续使用旧流程。
- 不自动推送 Git、不发布版本、不升级用户 Router、不改模型配置。
- 不自建任务平台/插件市场，不新增第二套生成引擎，不在这轮承诺所有操作系统与所有终端。
- 严格逐帧复刻、模型效果优化、自动配音/字幕质量提升，另列制作能力需求。
